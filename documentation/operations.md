# التشغيل: النشر، إضافة مشرف، البذر الآمن، Sentry، والمشاكل الشائعة

## 1. كيف يتم النشر

النشر **تلقائي** ولا يحتاج أوامر يدوية:

1. فرع جديد من `main` المحدّث (`feat/…`, `fix/…`, `docs/…`).
2. التغيير + الاختبارات + تحديث `docs/memory-bank/` **و** `documentation/` في نفس الـ PR.
3. فتح PR إلى `main` ← تعليق `@coderabbitai review` للمراجعة الآلية.
4. `ci.yml` (تحليل، اختبارات، بناء، فحص البذور، اختبارات القواعد) و `deploy.yml` (بناء + **قناة معاينة** `pr-<رقم>` لمدة 7
   أيام، ورابطها يُكتب تعليقًا على الـ PR) يجب أن ينجحا.
5. **Squash merge**. الدمج في `main` يشغّل `deploy.yml`: اختبارات القواعد ← نشر قواعد وفهارس Firestore ← نشر Hosting
   (الموقع + موقع التحويل القديم). مهمة البناء تولّد أيضًا `sitemap.xml` من Firestore **قراءة فقط** (PR #30،
   `tool/build_sitemap.sh`)، وعند فشلها تُنشر الخريطة الثابتة دون أن يفشل النشر.
6. تأكد أن تشغيل **Deploy to Firebase** على `main` أخضر في تبويب Actions.

ممنوع: الدفع مباشرة إلى `main`، و `git push --force`، وتعديل بيانات الإنتاج يدويًا من الكود.

النشر اليدوي (للطوارئ فقط، بحساب له صلاحية):
`flutter build web --release --dart-define=RECAPTCHA_SITE_KEY=<المفتاح> && bash tool/build_sitemap.sh build/web/sitemap.xml && python3 tool/fingerprint_icon_fonts.py build/web && npx firebase-tools deploy --only hosting:app,hosting:legacy-redirect --project asafra-church-portal`
(خطوة الخريطة تحتاج `GOOGLE_APPLICATION_CREDENTIALS`؛ بدونه تُبقي `web/sitemap.xml` الثابتة مع تحذير ولا توقف الأمر.)

### الأسرار والمتغيرات (GitHub ← Settings ← Secrets and variables ← Actions)

| الاسم | النوع | الاستخدام |
|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT_ASAFRA_CHURCH_PORTAL` | سر | مفتاح JSON لحساب خدمة النشر (يُحفظ بلا أي أحرف زائدة)؛ تستخدمه مهام النشر والمعاينة والبذر، ومهمة البناء لقراءة المحتوى العام فقط لتوليد `sitemap.xml` |
| `FIREBASE_WEB_API_KEY` | متغير أو سر اختياري | غير مطلوب؛ يُستخرج تلقائيًا من `lib/firebase_options.dart` لإرسال رابط تعيين كلمة المرور للمشرف الجديد |
| `RECAPTCHA_SITE_KEY` | متغير | مفتاح reCAPTCHA Enterprise للويب (للنشر من `main` فقط) |
| `SENTRY_DSN` | متغير اختياري | غير مطلوب؛ الكود فيه DSN عام |
| `SENTRY_AUTH_TOKEN` | سر (غير موجود بعد) | لرفع source maps مستقبلًا |

### أمان مفاتيح Firebase وتنبيهات GitHub Secret Scanning

مفتاح الويب في `lib/firebase_options.dart` هو **معرّف عام للمشروع** (Client Identifier) وليس سرًا وفق توثيق Google و Firebase الرسمي. يُدمج المفتاح في كود الواجهة ويُرسل علنًا في طلبات المتصفح، وحماية البيانات تعتمد على قواعد أمان Firestore (`firestore.rules`). أما App Check فهو مفروض على Firebase AI Logic فقط، وليس على Firestore، ولا يعمل على الويب إلا عند ضبط `RECAPTCHA_SITE_KEY`.
- تنبيه الأمان في GitHub (Secret Scanning Alert #1) جرى إغلاقه كـ **`false_positive`**.
- في workflow البذر (`.github/workflows/seed.yml`) لا يُكتب المفتاح كنص صريح، بل يُستخرج تلقائيًا أو يُقرأ من متغيرات البيئة.
- لحماية إضافية (Defense in depth): يُوصى في Google Cloud Console بحصر الـ APIs المسموح بها للمفتاح (API restrictions) على: Identity Toolkit و Firestore و App Check و Token Service. وإذا رغبت في تطبيق قيود نطاقات المتصفح (HTTP referrers) على مفتاح الويب، يجب توفير مفتاح منفصل للـ CI عبر GitHub Secret باسم `FIREBASE_WEB_API_KEY` حتى لا تُحظر طلبات `curl` في سير عمل البذر لعدم وجود متصفح (HTTP referrer).

## 2. إضافة مشرف

الطريقة المفضلة (بدون أي بذر):

1. Firebase Console ← **Authentication** ← **Add user** (بريد + كلمة مرور مؤقتة)، وانسخ الـ **UID**.
2. `/admin` بحساب **مالك** ← **«المشرفون»** ← **«إضافة مشرف»**: الـ UID، البريد، والدور («محرر» أو «مالك (يدير المشرفين)»).
3. أبلغ المشرف بالدخول وتغيير كلمة المرور عبر «نسيت كلمة المرور؟».

- لا تستطيع تغيير دورك أو حذف نفسك (حتى يبقى مالك دائمًا). يُنصح بمالكَين على الأقل.
- **أول مالك فقط** (عندما لا يوجد مالك): في Firestore أنشئ `admins/<UID>` = `{"email": "...", "role": "owner"}` من
  الكونسول. (يوجد أيضًا مدخل `admin_email` في workflow البذر، لكنه يشغّل البذر كله — انظر التحذير بالأسفل؛ لا تستخدمه
  إلا بموافقة المالك ومع `only`.)

## 3. البذر (Seed) بأمان

`assets/seed/seed.json` هو المحتوى الأولي، يُولَّد من `tool/gen_seed.py` (لا يُعدَّل يدويًا؛ CI يفشل إن لم يتطابق).
يُرفع إلى Firestore بـ `tool/seed_firestore.js` أو workflow **Seed Firestore** (يدوي، بيئة `production`).

| الخيار | ماذا يفعل | الخطر |
|---|---|---|
| (بدون خيارات) | ينشئ كل مستند **غير موجود** ويترك الموجود | **يعيد إنشاء ما حذفه المشرفون** (مثل العيادات الـ 11 المحذوفة في 3 نوفمبر 2026) |
| `only=a,b` | مجموعات محددة فقط | أقل خطرًا — استخدمه دائمًا |
| `fill_missing` | **بالإضافة** للإنشاء العادي، يضيف الحقول الناقصة للمستندات الموجودة دون تغيير أي قيمة | لا يقلل الخطر: ما زال **يعيد إنشاء المستندات المحذوفة**؛ استخدمه دائمًا مع `only` |
| `--dry-run` (محليًا) | يطبع ما سيفعل دون كتابة | آمن |
| **`force`** | **يستبدل المستندات الموجودة** ويحذف المعرفات المتقاعدة | **ممنوع على الإنتاج** — يمسح تعديلات اللوحة |

القواعد:
- **لا تشغّل البذر على الإنتاج بدون موافقة صريحة من المالك**، ولا تستخدم `force` أبدًا.
- لا تشغّله أبدًا لمجموعة `clinics` أو بدون `only`.
- الخياران الوحيدان اللذان يقللان الخطر هما `only` (مجموعات أقل) و `--dry-run` (بدون كتابة).
- جرّب أولًا: `cd tool && npm install && node seed_firestore.js --dry-run --only <مجموعة>`.
- لحذف عنصر مبذور بشكل دائم: احذفه من `tool/gen_seed.py` **وأضف معرفه** تحت اسم مجموعته في قاموس `retired` داخل
  نفس الملف (المولّد يرفض حذف معرف دون تقاعده، ويكتب `tool/retired_seed_ids.json`)، ثم `python3 tool/gen_seed.py`.

## 4. متابعة Sentry

1. ادخل <https://sentry.io> ← المؤسسة `kerollos-0e` ← المشروع `church-portal` ← **Issues**.
2. فلتر **Environment = `production`** (الموقع المباشر). `preview` = معاينات PR، `ci` = بناء CI.
3. لكل مشكلة: الوسم `route` (الصفحة)، و `section` (مثل `content:clinics` لفشل تحميل مجموعة، `assistant`، `contact`، `admin`).
4. اختبار الوصول: في `/admin` ← «الأقسام والصفحة الرئيسية» ← «تقارير الأخطاء» ← **«إرسال خطأ تجريبي»** (للمالك)،
   ثم ابحث عن مشكلة `Test error from /admin (ignore)` بوسم `test: true`.
5. **Uptime**: مراقب uptime في Sentry يرسل تنبيهًا إن توقف الموقع. التنبيهات تصل لبريد المطوّر. Seer / Autofix مفعّل.
6. لإيقاف كل التقارير فورًا: مفتاح «إرسال تقارير الأخطاء (Sentry)».
7. الخطة التعليمية تنتهي **3 نوفمبر 2027**.

## 6. تشغيل ونشر تطبيق Android وتحديثاته (ADR-058)

تطبيق Android يُبنى كحزمة أندرويد مستقلة (APK) منفصلة حسب المعمارية لتوفير الحجم واستهلاك البيانات، ويعمل بالتوازي مع البوابة الإلكترونية دون أي تكلفة إضافية على خطة Spark المجانية (+0 قراءات/كتابات Firestore للزوار).

### مسار البناء والنشر التلقائي (`.github/workflows/android.yml`)
- **المُشغّل (Trigger):** يُشغّل المسار تلقائياً عند دفع وسم إصدار جديد بالصيغة `apk-v*` (مثل `apk-v1.0.0`)، أو يدوياً عبر `workflow_dispatch` للمعاينة والفحص.
- **الإصدار في المستودع:** `pubspec.yaml` هو `1.0.1+2` (الاسم `1.0.1`، رقم البناء `2`). رقم البناء أعلى من `1` حتى يعرض التطبيق المثبت التحديث. وسم `apk-v1.0.1` لا يُدفع مع تغيير الرقم؛ التحميل العام يبقى آخر وسم منشور (`apk-v1.0.0`) إلى أن يُدفع الوسم.
- **الحزم المنفصلة (Split APKs):** يُنتج المسار حزمتين منفصلتين:
  - `church-portal-arm64.apk` (`app-arm64-v8a-release.apk`): للأجهزة الحديثة (64-bit).
  - `church-portal-arm32.apk` (`app-armeabi-v7a-release.apk`): للأجهزة القديمة (32-bit).
- **ميزانية الحجم الصارمة:** يفشل البناء في CI فوراً قبل الرفع أو النشر إذا تجاوز حجم حزمة `arm64` حد 20 ميجابايت (20,971,520 بايت)، أو حزمة `arm32` حد 18 ميجابايت (18,874,368 بايت).
- **الضغط والتوافق:** يُستخدم مصغّر ومحسّن الأكواد R8 (`isMinifyEnabled = true`, `isShrinkResources = true`) مع إزالة الموارد الفائضة، وتفعيل `coreLibraryDesugaring` عبر حزمة `com.android.tools:desugar_jdk_libs:2.1.5` مع Java 17 لدعم دوال التواريخ والوقت الحديثة على إصدارات أندرويد القديمة (minSdk 21).

### التوقيع الرقمي ومفاتيح الإنتاج (Keystore & Signing)
- تُحفظ مفاتيح التوقيع للإنتاج في أسرار GitHub (GitHub Secrets):
  - `ANDROID_KEYSTORE_BASE64`: ملف `release.jks` مشفر بـ base64.
  - `KEYSTORE_PASSWORD` / `ANDROID_KEYSTORE_PASSWORD`: كلمة مرور مستودع المفاتيح.
  - `KEY_ALIAS` / `ANDROID_KEY_ALIAS`: الاسم التعريفي للمفتاح.
  - `KEY_PASSWORD` / `ANDROID_KEY_PASSWORD`: كلمة مرور المفتاح الخاص.
- **التراجع التلقائي (Debug Fallback):** في مسارات الفحص والـ PR أو عند غياب أسرار التوقيع محلياً، يتراجع بناء Gradle تلقائياً إلى توقيع الـ debug لتمكين المطورين والمختبرين من تجميع واختبار الحزمة دون توقف. أما وسوم الإصدار `apk-v*` فتفرض وجود أسرار التوقيع وتفشل بصوت عالٍ إن غابت لمنع نشر حزمة غير موقعة رقمياً.

### ملف بيان التحديثات (`version.json`)
- تُشغّل أداة `tool/make_apk_manifest.mjs` بعد بناء الحزم لحساب بصمات SHA-256 وأحجام الملفات بدقة واستخراج أرقام البناء ورسائل الإصدار باللغتين العربية والإنجليزية.
- يُنشر ملف البيان إلى Firebase Hosting على المسار `/app/android/version.json` (وتنقله كل عملية نشر للكود `deploy.yml` من الموقع الحي حتى لا يختفي) وتُضبط ترويسات التخزين المؤقت له في `firebase.json` بـ `no-cache, no-store, must-revalidate` لضمان معرفة الهواتف بوجود أي تحديث فوري دون كاش قديم.

### خط مزامنة قراءات القطمارس والسنكسار (Cloudflare Worker & Readings Syncer — ADR-063)
- تم نقل مسار الجلب والمزامنة اليومية من مسار GitHub Actions القديم (`synaxarium.yml`) إلى محرك Cloudflare Worker عبر المؤقت الزمني الرابع:
  - `0 16 * * *` (Cron 4): يعمل يومياً عند الساعة 18:00 بتوقيت القاهرة (16:00 UTC) مع بدء اليوم الطقسي القبطي الجديد في العشية.
  - يستدعي المحرك دالة `syncDailyReadingsAndSynaxarium` (`tool/readings_syncer.js`) لجلب قراءات القطمارس ونصوص السنكسار من Katameros API (`api.katameros.app`).
  - يعتمد الحفظ المزدوج: كتابة الوثيقة في مسار Firestore REST `readings/<YYYY-MM-DD>` عبر حساب الخدمة، وتخزين نسخة مؤقتة في Cloudflare KV تحت المفتاح `reading:<YYYY-MM-DD>` مع وقت صلاحية (TTL) لمدة 7 أيام.
  - يدعم عدم التكرار (Idempotency): إذا كانت القراءات موجودة وطازجة في KV يتم تخطي إعادة الكتابة ما لم يُطلب فرض التحديث.
- ألغى هذا النقل الحاجة لمسار GitHub Actions القديم ومسار منع السبات (`keepalive.yml`) وضمن استقرار المهام السحابية وفق بنية Zero-Budget.

### آلية التحديث من داخل التطبيق (In-App Updates)
- يفحص التطبيق ملف البيان `/app/android/version.json` من الاستضافة عندما يكون `installApkBuild` في لوحة التحكم أكبر من رقم بناء التطبيق.
- عند توفر إصدار أحدث (`build > currentBuild`) يظهر شريط تنبيه للمستخدم.
- يدعم التحميل استئناف التنزيل عبر ترويسة `Range` في HTTP عند انقطاع الشبكة.
- يتحقق التطبيق إلزامياً من مطابقة بصمة SHA-256 للحزمة المحملة مع البيان، ويتأكد من توقيع الحزمة بنفس شهادة التطبيق المثبت عبر `PackageManager`.
- يطلب التطبيق إذن تثبيت الحزم غير المعروفة (`REQUEST_INSTALL_PACKAGES`) إن لم يكن ممنوحاً، ثم يفتح موجه التثبيت عبر `FileProvider` (`${applicationId}.updates`).
- إن كان رقم البناء الحالي أقل من `minSupportedBuild`، لا يمكن إخفاء شريط التحديث، لكن التطبيق يبقى صالحًا للاستخدام (لا يُمنع المستخدم من التطبيق) — يُستخدم فقط لإصلاح أمني. تُضبط القيمة عند الإصدار بالمتغير `APK_MIN_SUPPORTED_BUILD` في إعدادات GitHub (الافتراضي 1).

### أداء التطبيق، شاشة البداية والتنقل الموحد (ADR-062, ADR-064)
- **شاشة بدء التشغيل الرسمية (Launch Splash):** تم ضبط لون خلفية بدء تشغيل التطبيق على لون الكريم `#FBF3E4` مع ختم الكنيسة لجميع إصدارات أندرويد (بما فيها Android 12+ عبر `windowSplashScreenBackground` في `values-v31` والوضع الليلي)، لمنع الوميض الأبيض أو الأسود عند الفتح البارد (`INV-SPLASH-01`).
- **سلاسة الرسوميات وتوفير الطاقة والبطارية (`INV-PERF-01`):** تعطيل محرك الأنيميشن اللحظي التكراري ومحرك تقريب Ken Burns وطبقات الأنيميشن الحركية في الهيرو لتطبيق أندرويد وiOS والشاشات التي يقل عرضها عن 600 بكسل (`heroAmbientLoopAllowed() == false`) لتفادي هبوط الإطارات واستهلاك المعالج، مع الإبقاء على تشغيل الفيديو عبر وحدة فك التشفير بالعتاد. كما تم إيقاف الميقاتيات التكرارية لنقطة البث الحي (`_PulseDot`) ومربعات التحميل الهيكلية (`SkeletonBox`) على الهواتف، وتجاوز طبقات التلاشي (`Reveal`) أثناء التمرير لتفادي كلفة `saveLayer`.
- **مساحة شريط التطبيق العلوي للهواتف (`INV-APPBAR-01`):** حذف زر تبديل اللغة من شريط التطبيق العلوي على الشاشات التي يقل عرضها عن 600 بكسل لتوفير مساحة أفقية تتجاوز 54 نقطة، مما يمنح عنوان الكنيسة المختصر مساحة قراءة رحبة ويمنع تداخله نهائياً مع لسان ختم الكنيسة، مع بقاء زر تبديل اللغة متاحاً بسهولة داخل القائمة الجانبية (Drawer).
- **التنقل وسهم الرجوع الفردي (`INV-NAV-01`, `INV-NAV-02`):** صفحة تفاصيل البطارية (`/notifications/battery`) تعتمد تخطيط الصفحة القياسي بدون شريط مكرر، ويعود زر الرجوع بها وسهم النظام إلى شاشة الإشعارات (`/notifications`). في صفحات التفاصيل (`ItemDetailPage`)، يظهر سهم الرجوع فقط في شريط التطبيق العلوي للهواتف لمنع تكرار الأسهم.
- **انسيابية شاشة تفضيلات الإشعارات (`/notifications`):** إزالة بطاقة تحسين بطارية المصنعين الدائمة من واجهة الإشعارات لتتدفق التفضيلات مباشرة من بطاقة الحالة إلى قنوات الإشعارات والتذكيرات دون تشويش بصري، مع طلب أذونات النظام التفاعلية فور النقر على أي مفتاح إشعار إن لم تكن ممنوحة مسبقاً.

### مفتاح إشعارات المتصفح على الموقع الحي (ADR-066)

زر «السماح بإشعارات المتصفح» يبقى معطّلًا وعبارة «إشعارات المتصفح غير مُعدّة على الموقع بعد» تظهر عندما يكون «تشغيل الإشعارات» مفعّلًا ولا يوجد مفتاح عام. هذا ليس عطل المتصفح: الملفان `/firebase-messaging-sw.js` و`/push_client.js` موجودان. إن كان المتصفح نفسه لا يدعم الإشعارات تظهر عبارة «هذا المتصفح لا يدعم تلقي الإشعارات.» لا عبارة الإعداد.

جهّز المفتاح العام مرة واحدة:

1. Firebase Console → المشروع `asafra-church-portal` → Project settings → Cloud Messaging → Web Push certificates. إن لم يوجد زوج مفاتيح اضغط Generate key pair. انسخ **المفتاح العام** فقط (نحو ٨٠–١٠٠ حرفًا من حروف وأرقام و`-` و`_`). لا تنسخ المفتاح الخاص ولا تضعه في GitHub.
2. أحد الطريقين يكفي:
   - **من لوحة التحكم (يعمل فور الحفظ، بلا إعادة نشر):** `/admin` → «الإشعارات» → «إعدادات تقنية» → «مفتاح إشعارات المتصفح (VAPID public key)» → الصق → «حفظ الإعدادات».
   - **من GitHub (يحتاج إعادة نشر):** Settings → Secrets and variables → Actions → Variables → متغير باسم `WEB_PUSH_VAPID_KEY` (متغير عام، ليس سرًا) → الصق المفتاح العام → ادفع إلى `main` أو أعد تشغيل نشر الموقع. البناء يمرّره كـ `--dart-define=WEB_PUSH_VAPID_KEY`. يُستخدم فقط عندما يكون حقل اللوحة فارغًا.
3. المفتاح المكتوب في اللوحة يغلب متغير GitHub. لإيقاف إشعارات المتصفح فورًا أوقف «تشغيل الإشعارات». مسح الحقل وحده لا يوقف الزر ما دام المتغير مضبوطًا في آخر بناء؛ أزل المتغير وأعد النشر إن أردت إسقاط هذا الاحتياط.

### تشغيل إشعارات الويب وتوجيه المتصفحات (Web Push & Browser Guidance — ADR-065)
1. **تجربة طلب الإذن التفاعلية (User Gesture & Onboarding):**
   - التزاماً بسياسات أمان المتصفحات (Chrome, Safari, Firefox, Edge)، لا يتم طلب إذن الإشعارات تلقائياً عند فتح شاشة `/notifications` نهائياً (Zero page-load permission call) حتى لا يُصنف الموقع كمزعج أو يُحظر من قِبل المتصفح.
   - إذا كان الإذن في حالته الافتراضية (`default`)، تعرض الصفحة بطاقة بارزة تدعو المستخدم للسماح: «السماح بإشعارات المتصفح»، مع توضيح الفائدة.
   - النقر على أي مفتاح إشعار يطلب إذن المتصفح تفاعلياً؛ وفور الموافقة يتم استخراج رمز FCM للويب وتسجيل المواضيع المحددة فوراً في طابور `push_queue` بـ Firestore عبر `WebPushRepository`.
2. **متصفحات التطبيقات الداخلية (In-App Browsers):**
   - المتصفحات المدمجة داخل تطبيقات التواصل (مثل Telegram و WhatsApp و Facebook و Instagram و TikTok والمتصفحات المدمجة عبر Android WebView `; wv`) تحظر واجهات برمجة إشعارات الويب (Push API & Service Workers).
   - تكتشف الصفحة هذه البيئات تلقائياً وتعرض بطاقة إرشادية توضح للمستخدم ضرورة فتح الموقع في المتصفح الأساسي، مع زر مخصص «نسخ الرابط للمتصفح» ينسخ الرابط بضغطة واحدة مع رسالة تأكيد.
3. **أجهزة iPhone ومتصفح Safari (iOS 16.4 وما بعده):**
   - تفرض Apple عدم إمكانية استقبال إشعارات الويب إلا بعد إضافة الموقع إلى الشاشة الرئيسية كتطبيق ويب تقدمي (PWA).
   - عند فتح الصفحة في تبويب Safari العادي، تعرض واجهة الإشعارات دليلاً بصرياً من 3 خطوات («إضافة إلى الصفحة الرئيسية» Add to Home Screen).
   - بمجرد تشغيل التطبيق من أيقونة الشاشة الرئيسية (`isStandalone: true`)، تختفي بطاقة التثبيت وتظهر فوراً بطاقة طلب الإذن ومفاتيح القنوات.
4. **حل مشكلة حظر الإذن (Permission Denied):**
   - إذا اختار المستخدم حظر الإشعارات مسبقاً (`denied`)، تعرض الصفحة دليلاً لاستعادة الإذن من إعدادات المتصفح:
     - **متصفح Google Chrome (كمبيوتر وأندرويد):** النقر على أيقونة القفل أو شريط الضبط بجوار رابط الموقع في شريط العناوين -> «أذونات الموقع» (Site settings) -> تغيير «الإشعارات» (Notifications) إلى «سماح» (Allow).
     - **متصفح Safari على أجهزة Mac (macOS Safari):** فتح Safari ← الإعدادات (Settings) ← مواقع الويب (Websites) ← الإشعارات (Notifications) ← تحديد موقع الكنيسة وتغييره إلى «سماح» (Allow).
     - **تطبيق الويب المثبت على iPhone (iOS PWA):** الذهاب إلى إعدادات الهاتف (iPhone Settings) ← الإشعارات (Notifications) ← كنيسة مكسيموس ودوماديوس (Church App) ← تفعيل «السماح بالإشعارات» (Allow Notifications).
   - بعد تعديل الإذن، ينقر المستخدم على زر «إعادة فحص الإذن» لفحص الحالة وتحديث الواجهة والمفاتيح فوراً دون الحاجة لتحديث الصفحة بالكامل.

### استكشاف أخطاء أندرويد وتوفير البطارية (OEM Battery Troubleshooting)
- تميل بعض واجهات المصنعين العدوانية (Xiaomi MIUI/HyperOS, Oppo ColorOS, Realme UI, Huawei EMUI, Samsung OneUI, Vivo Funtouch) إلى قتل التطبيقات في الخلفية أو تأخير المنبهات الدقيقة وحظر البدء التلقائي.
- عند شكوى المستخدمين من تأخر تذكيرات القداسات أو إشعارات قراءات القطمارس والآية اليومية:
  1. توجيه المستخدم لصفحة التشخيص ودليل تحسين البطارية داخل التطبيق: `/notifications/battery`.
  2. تعرض الصفحة فحصاً فورياً لـ: إذن الإشعارات (`POST_NOTIFICATIONS`)، إذن المنبهات الدقيقة (`SCHEDULE_EXACT_ALARM`)، استثناء توفير البطارية (Battery Optimization Exemption)، وحالة عمل مهمة التجديد الدورية (`WorkManager`).
  3. توفر الصفحة روابط مباشرة تفتح إعدادات النظام المخصصة لنوع الهاتف (Auto-start / Background Activity).

### محرك إرسال الإشعارات المجدولة (Cloudflare Worker & FCM Sender — ADR-059 / ADR-060)
- يعمل المحرك كـ Cloudflare Worker مجدول بثلاثة مؤقتات زمنية (3 Crons) في `wrangler.toml`:
  1. `*/15 * * * *` (Cron 1): فحص جدول الإشعارات المجدولة، إرسال تنبيهات المواسم اليومية، وإرسال تذكيرات القداسات المستحقة لمتصفحات الويب باستخدام شروط FCM (`'web_rem_...' in topics && !('app_...' in topics)`).
  2. `7,22,37,52 * * * *` (Cron 2): تفريغ طابور اشتراكات المتصفح (`push_queue`) وإضافتها أو حذفها من مواضيع FCM عبر Google IID REST بمعدل يصل إلى 10 وثائق لكل دورة (مع سقف 50 عملية و20 طلبًا فرعيًا)، وتحديث وثيقة `meta/push_topics`.
  3. `3 2,8,14,20 * * *` (Cron 3): مخطط تذكيرات الويب الذي يقرأ جدول القداسات والاجتماعات وأحداث اليوم كل 6 ساعات، ويستخرج المواضيع المستحقة للأيام القادمة مرتبة زمنيًا ويحفظها في `meta/push_plan`.
- **نشر المحرك وذاكرة التخزين (KV Cache):**
  - يعتمد المحرك على مساحة تخزين `PUSH_KV` في Cloudflare لتخزين رمز الوصول المؤقت لـ Google OAuth2 (مستوى ثانٍ L2 بعد الذاكرة L1)، مما يقلل من سك الرموز إلى مرة واحدة فقط في الساعة تقريبًا.
  - لنشر المحرك أو تحديثه: يُنفَّذ الأمر `npx wrangler deploy` (يلزم إجراء ذلك قبل الدمج إلى فرع `dev` أو `main`).
- **أسرار المحرك (Worker Secrets):**
  - تُضبط في لوحة Cloudflare أو عبر أداة `wrangler secret put`:
    - `FIREBASE_PROJECT_ID`: معرف مشروع فايربيس (`asafra-church-portal`).
    - `FIREBASE_CLIENT_EMAIL`: البريد الإلكتروني لحساب الخدمة (Service Account).
    - `FIREBASE_PRIVATE_KEY`: المفتاح الخاص لحساب الخدمة بصيغة PEM (يبدأ بـ `-----BEGIN PRIVATE KEY-----`).
    - `SENTRY_DSN`: رابط Sentry لرصد أي أخطاء وقت التشغيل بدون جمع بيانات شخصية.
    - `SENTRY_CRON_MONITOR_ID`: معرف مراقبة دقات المحرك في Sentry Crons للإنذار عند تعطل المهام.
- **حدود واستهلاك الكوتا (Spark Quota Protection):**
  - يعتمد المحرك على استعلام REST `:batchGet` يقرأ وثيقتين فقط في كل ربع ساعة، بالإضافة إلى استعلام المواسم مرة واحدة عند منتصف الليل بتوقيت القاهرة (~197 قراءة فقط يوميًا).
  - يحدد المحرك سقف الإرسال بحد أقصى 16 إشعار FCM أو ≤ 25 طلبًا فرعيًا لكل تشغيل.
  - لا توجد أي واجهة HTTP عامة تقبل أوامر إرسال (لا يوجد مسار `POST /trigger`) لمنع التلاعب أو استنزاف الكوتا.
- **المسار الاحتياطي اليدوي في GitHub Actions (`.github/workflows/push-sender.yml`):**
  - مسار يمكن تشغيله يدويًا عند الحاجة (`workflow_dispatch`) من GitHub Actions لتشغيل السكربت الاحتياطي `node tool/push_sender.js` بواسطة Node 22.
