# التشغيل: النشر، إضافة مشرف، البذر الآمن، Sentry، والمشاكل الشائعة

## 1. كيف يتم النشر

النشر **تلقائي** ولا يحتاج أوامر يدوية:

1. فرع جديد من `main` المحدّث (`feat/…`, `fix/…`, `docs/…`).
2. التغيير + الاختبارات + تحديث `docs/memory-bank/` **و** `documentation/` في نفس الـ PR.
3. فتح PR إلى `main` ← تعليق `@coderabbitai review` للمراجعة الآلية.
4. `ci.yml` (تحليل، اختبارات، بناء، فحص البذور، اختبارات القواعد) و `deploy.yml` (بناء + **قناة معاينة** `pr-<رقم>` لمدة 7
   أيام، ورابطها يُكتب تعليقًا على الـ PR) يجب أن ينجحا.
5. **Squash merge**. الدمج في `main` يشغّل `deploy.yml`: اختبارات القواعد ← نشر قواعد وفهارس Firestore ← نشر Hosting
   (الموقع + موقع التحويل القديم).
6. تأكد أن تشغيل **Deploy to Firebase** على `main` أخضر في تبويب Actions.

ممنوع: الدفع مباشرة إلى `main`، و `git push --force`، وتعديل بيانات الإنتاج يدويًا من الكود.

النشر اليدوي (للطوارئ فقط، بحساب له صلاحية):
`flutter build web --release --dart-define=RECAPTCHA_SITE_KEY=<المفتاح> && python3 tool/fingerprint_icon_fonts.py build/web && npx firebase-tools deploy --only hosting:app,hosting:legacy-redirect --project asafra-church-portal`

### الأسرار والمتغيرات (GitHub ← Settings ← Secrets and variables ← Actions)

| الاسم | النوع | الاستخدام |
|---|---|---|
| `FIREBASE_SERVICE_ACCOUNT_ASAFRA_CHURCH_PORTAL` | سر | مفتاح JSON لحساب خدمة النشر (يُحفظ بلا أي أحرف زائدة) |
| `FIREBASE_WEB_API_KEY` | متغير أو سر اختياري | غير مطلوب؛ يُستخرج تلقائيًا من `lib/firebase_options.dart` لإرسال رابط تعيين كلمة المرور للمشرف الجديد |
| `RECAPTCHA_SITE_KEY` | متغير | مفتاح reCAPTCHA Enterprise للويب (للنشر من `main` فقط) |
| `SENTRY_DSN` | متغير اختياري | غير مطلوب؛ الكود فيه DSN عام |
| `SENTRY_AUTH_TOKEN` | سر (غير موجود بعد) | لرفع source maps مستقبلًا |

### أمان مفاتيح Firebase وتنبيهات GitHub Secret Scanning

مفتاح الويب في `lib/firebase_options.dart` هو **معرّف عام للمشروع** (Client Identifier) وليس سرًا وفق توثيق Google و Firebase الرسمي. يُدمج المفتاح في كود الواجهة ويُرسل علنًا في طلبات المتصفح، وحماية البيانات تعتمد على قواعد أمان Firestore (`firestore.rules`). أما App Check فهو مفروض على Firebase AI Logic فقط، وليس على Firestore، ولا يعمل على الويب إلا عند ضبط `RECAPTCHA_SITE_KEY`.
- تنبيه الأمان في GitHub (Secret Scanning Alert #1) جرى إغلاقه كـ **`false_positive`**.
- في workflow البذر (`.github/workflows/seed.yml`) لا يُكتب المفتاح كنص صريح، بل يُستخرج تلقائيًا أو يُقرأ من متغيرات البيئة.
- لحماية إضافية (Defense in depth): يُوصى في Google Cloud Console بحصر الـ APIs المسموح بها للمفتاح (API restrictions) على: Identity Toolkit و Firestore و App Check و Token Service. وإذا رغبت في تطبيق قيود نطاقات المتصفح (HTTP referrers) على مفتاح الويب، يجب توفير مفتاح منفصل للـ CI عبر GitHub Secret باسم `FIREBASE_WEB_API_KEY` حتى لا تُحظر طلبات `curl` في سير عمل البذر لعدم وجود متصفح (HTTP referrer).

## 2. إضافة مشرف

الطريقة المفضلة (بدون أي بذر):

1. Firebase Console ← **Authentication** ← **Add user** (بريد + كلمة مرور مؤقتة)، وانسخ الـ **UID**.
2. `/admin` بحساب **مالك** ← **«المشرفون»** ← **«إضافة مشرف»**: الـ UID، البريد، والدور («محرر» أو «مالك (يدير المشرفين)»).
3. أبلغ المشرف بالدخول وتغيير كلمة المرور عبر «نسيت كلمة المرور؟».

- لا تستطيع تغيير دورك أو حذف نفسك (حتى يبقى مالك دائمًا). يُنصح بمالكَين على الأقل.
- **أول مالك فقط** (عندما لا يوجد مالك): في Firestore أنشئ `admins/<UID>` = `{"email": "...", "role": "owner"}` من
  الكونسول. (يوجد أيضًا مدخل `admin_email` في workflow البذر، لكنه يشغّل البذر كله — انظر التحذير بالأسفل؛ لا تستخدمه
  إلا بموافقة المالك ومع `only`.)

## 3. البذر (Seed) بأمان

`assets/seed/seed.json` هو المحتوى الأولي، يُولَّد من `tool/gen_seed.py` (لا يُعدَّل يدويًا؛ CI يفشل إن لم يتطابق).
يُرفع إلى Firestore بـ `tool/seed_firestore.js` أو workflow **Seed Firestore** (يدوي، بيئة `production`).

| الخيار | ماذا يفعل | الخطر |
|---|---|---|
| (بدون خيارات) | ينشئ كل مستند **غير موجود** ويترك الموجود | **يعيد إنشاء ما حذفه المشرفون** (مثل العيادات الـ 11 المحذوفة في 3 نوفمبر 2026) |
| `only=a,b` | مجموعات محددة فقط | أقل خطرًا — استخدمه دائمًا |
| `fill_missing` | **بالإضافة** للإنشاء العادي، يضيف الحقول الناقصة للمستندات الموجودة دون تغيير أي قيمة | لا يقلل الخطر: ما زال **يعيد إنشاء المستندات المحذوفة**؛ استخدمه دائمًا مع `only` |
| `--dry-run` (محليًا) | يطبع ما سيفعل دون كتابة | آمن |
| **`force`** | **يستبدل المستندات الموجودة** ويحذف المعرفات المتقاعدة | **ممنوع على الإنتاج** — يمسح تعديلات اللوحة |

القواعد:
- **لا تشغّل البذر على الإنتاج بدون موافقة صريحة من المالك**، ولا تستخدم `force` أبدًا.
- لا تشغّله أبدًا لمجموعة `clinics` أو بدون `only`.
- الخياران الوحيدان اللذان يقللان الخطر هما `only` (مجموعات أقل) و `--dry-run` (بدون كتابة).
- جرّب أولًا: `cd tool && npm install && node seed_firestore.js --dry-run --only <مجموعة>`.
- لحذف عنصر مبذور بشكل دائم: احذفه من `tool/gen_seed.py` **وأضف معرفه** تحت اسم مجموعته في قاموس `retired` داخل
  نفس الملف (المولّد يرفض حذف معرف دون تقاعده، ويكتب `tool/retired_seed_ids.json`)، ثم `python3 tool/gen_seed.py`.

## 4. متابعة Sentry

1. ادخل <https://sentry.io> ← المؤسسة `kerollos-0e` ← المشروع `church-portal` ← **Issues**.
2. فلتر **Environment = `production`** (الموقع المباشر). `preview` = معاينات PR، `ci` = بناء CI.
3. لكل مشكلة: الوسم `route` (الصفحة)، و `section` (مثل `content:clinics` لفشل تحميل مجموعة، `assistant`، `contact`، `admin`).
4. اختبار الوصول: في `/admin` ← «الأقسام والصفحة الرئيسية» ← «تقارير الأخطاء» ← **«إرسال خطأ تجريبي»** (للمالك)،
   ثم ابحث عن مشكلة `Test error from /admin (ignore)` بوسم `test: true`.
5. **Uptime**: مراقب uptime في Sentry يرسل تنبيهًا إن توقف الموقع. التنبيهات تصل لبريد المطوّر. Seer / Autofix مفعّل.
6. لإيقاف كل التقارير فورًا: مفتاح «إرسال تقارير الأخطاء (Sentry)».
7. الخطة التعليمية تنتهي **3 نوفمبر 2027**.

## 5. مشاكل شائعة وحلولها

| المشكلة | السبب المحتمل | الحل |
|---|---|---|
| تظهر في التذييل «تعرض البيانات المحفوظة مع التطبيق» على الموقع المباشر | تيار بيانات ما زال على النسخة المدمجة. مشكلة مفتوحة؛ الاشتباه: مجموعة **فارغة** على الخادم (مثل `clinics` حين كانت فارغة بعد الحذف، أو `alerts` إن حُذفت كل التنويهات) عندما لا يُجيب فحص `settings/church` في 8 ثوانٍ، لأن القائمة الفارغة لا «تثبت نفسها» | لا تُخفِ الرسالة. شخّص على قناة المعاينة أي مفتاح في `_fallbackStreams` يبقى معلّمًا، ثم أصلح ذلك التيار (`11-open-tasks.md`) |
| حفظ في اللوحة يفشل بـ `permission-denied` | حقل غير مسموح في `firestore.rules`، أو طول أكبر من الحد، أو الحساب ليس مشرفًا | راجع حدود الحقل؛ المطور يضيف الحقل للقواعد والنموذج والمخطط والبذور معًا |
| المساعد غير ظاهر | أحد المفتاحين («قسم اسأل الكنيسة ظاهر» / «تفعيل المساعد الذكي») مُطفأ، أو App Check لم يعمل، أو أنت على قناة معاينة (بلا مفتاح reCAPTCHA) | فعّل المفتاحين؛ تحقق من `RECAPTCHA_SITE_KEY` وتسجيل App Check |
| المساعد يقول تعذّر الحصول على إجابة | حصة Gemini المجانية، أو App Check، أو نموذج مرفوض | راجع Sentry (`AssistantFailure`)؛ أفرغ حقل «النموذج» ليعود للافتراضي |
| زائر وصل لحد 3 أسئلة | الحد اليومي على الجهاز | يتجدد عند منتصف ليل القاهرة؛ يمكن رفعه في «أقصى عدد أسئلة لكل جهاز في اليوم» |
| صفحة قسم أو صفحة مخصصة تقول «غير متاحة» | `visible` مُطفأ، أو الرابط (slug) خطأ، أو قسم `customSections` / `customPages` موقوف | راجع العنصر والمفتاح |
| نوع رسالة جديد لا يظهر في النموذج | «ظاهر في النموذج» مُطفأ أو لم يُضغط «حفظ» | فعّله واحفظ (منذ PR #23 القائمة المحفوظة تحل محل الافتراضية دائمًا) |
| أيقونات تظهر فارغة بعد نشر | خط أيقونات قديم مخزّن | التبصيم في CI يحلها؛ تأكد أن خطوة `fingerprint_icon_fonts.py` تعمل |
| رسالة «عدّل مشرف آخر هذه البيانات» | تعديل متزامن | اضغط «إعادة التحميل» (تفقد التعديلات غير المحفوظة) أو انسخها أولًا |
| الثيم لم يتغير في المناسبة | «تبديل الثيم تلقائيًا» مُطفأ أو الفترة غير مضافة | فعّل التبديل وأضف الفترة في الجدول |
| الفيديو لا يعمل في الواجهة | «حركة الواجهة والفيديو» مُطفأ، أو الزائر فعّل تقليل الحركة/توفير البيانات | تظهر الصورة الثابتة أو اللوحة تلقائيًا؛ هذا سلوك مقصود. (لا توجد مكتبة فيديو يوتيوب بعد PR #25.) |
| الصورة «كبيرة جدًا حتى بعد الضغط» | أكبر من 700 ك.ب بعد الضغط | قصّ الصورة أو استخدم «رابط صورة» |
| بناء CI يفشل في «Seed JSON matches its generator» | عُدّل `gen_seed.py` دون إعادة التوليد | `python3 tool/gen_seed.py` ثم commit لـ `seed.json` وملفات المعرفات |
| اختبارات Flutter تفشل محليًا بأخطاء websocket | proxy | `export NO_PROXY=127.0.0.1,localhost no_proxy=127.0.0.1,localhost` |

## 6. مهام تشغيلية مفتوحة (ملخص)

- رفع source maps للويب ورموز Android إلى Sentry (يحتاج auth token).
- في Sentry: إيقاف تخزين IP وتفعيل مُنقّيات الخادم.
- توقيع release و Play Integrity لتطبيق Android.
- حد من جهة الخادم للمساعد.
- مراجعين مطلوبين لبيئة `production` في GitHub.
- القائمة الكاملة: [`docs/memory-bank/11-open-tasks.md`](../docs/memory-bank/11-open-tasks.md).
